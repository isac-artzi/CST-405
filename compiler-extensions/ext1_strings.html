Background

How MIPS represents strings

In MIPS, a string is a sequence of bytes in memory ending with a null byte (0x00). The value of a string variable is the address of its first byte — exactly like a char * in C. You store that address in a 4-byte stack slot, just like an integer.

MIPS assembly concept
.data
_str0:  .asciiz "hello world"   # null-terminated in .data

.text
        la  $t0, _str0          # load ADDRESS into register
        sw  $t0, -8($fp)        # store address on stack (string variable)

        lw  $a0, -8($fp)        # load address back
        li  $v0, 4              # syscall 4 = print_string
        syscall

The .data section in codegen.c

Look at codegen.c function generateCode(). It already emits a .data header before the .text header. You will add string literal entries there. Maintain a small table strLiterals[] — each entry maps a label like _str0 to the string content — populated during TAC traversal and flushed into .data before emitting code.

Session 1 — Strings as First-Class Values

🎯

Session 1 goal: Declare a string variable, assign a literal to it, and call output_string(). No concatenation yet.

1

Lexer — add the STRING_LITERAL token

In scanner.l, add a new token rule before the identifier rule so it takes priority. Handle escaped quotes (\") and backslash (\\) inside the string.

scanner.l
/* add after other token rules */
\"([^\\\"]|\\.)*\"   {
    /* strip surrounding quotes */
    yylval.sval = strndup(yytext+1, yyleng-2);
    return STRING_LITERAL;
}

Also add string as a keyword token STRING_KW so string s; can be declared. Add it to the keywords block the same way int is handled.

In the %union block of parser.y add char *sval; and declare %token <sval> STRING_LITERAL and %token STRING_KW.

2

AST — add NODE_STRING_LIT

In ast.h, add to the NodeType enum:

ast.h
NODE_STRING_LIT,   /* string literal: sval holds the text */

The existing ASTNode struct already has a char *sval field (used by identifiers). Reuse it. In ast.c, add a constructor:

ast.c
ASTNode *makeStringLit(const char *s) {
    ASTNode *n = makeNode(NODE_STRING_LIT);
    n->sval = strdup(s);
    return n;
}

In parser.y, add a grammar rule that matches STRING_LITERAL as an expression and calls makeStringLit(). Wire it into the existing expr production.

3

Symbol Table — add TYPE_STRING

In symtab.h, add TYPE_STRING to the VarType enum. In semantic.c, handle STRING_KW in the variable-declaration walk the same way int is mapped to TYPE_INT. String variables occupy one 4-byte slot on the stack (they store an address); no special size change needed.

⚠

Type-checking: For now, do not allow arithmetic on string variables. Add a check in semantic.c that emits a warning/error if a string variable appears in a numeric expression.

4

TAC & Code Generation

In tac.h, add a new opcode TAC_STRING_ASSIGN. Its arg1 field carries the string text; result is the destination variable. In tac.c, add a case in generateTAC() for NODE_STRING_LIT that allocates a new temporary and emits:

tac.c — generateTAC for NODE_STRING_LIT
TACInstr *instr = newTACInstr(TAC_STRING_ASSIGN);
instr->arg1   = strdup(node->sval);   /* literal text */
instr->result = newTemp();
emitTAC(instr);

In codegen.c, handle TAC_STRING_ASSIGN: allocate a label _strN, record it in your string table, emit la $tX, _strN and sw $tX, offset($fp). Before emitting the .text section, loop over the string table and emit .data entries:

codegen.c — .data section
for (int i = 0; i < numStrLiterals; i++) {
    fprintf(out, "%s:\t.asciiz \"%s\"\n",
            strLabels[i], strTexts[i]);
}

Handle output_string as a special built-in function call in codegen: load the address into $a0, set $v0 = 4, syscall.

Session 2 — Concatenation & Comparison

🎯

Session 2 goal: Implement string_concat(a, b) using a simple bump-pointer heap, and string_equal(a, b) using byte-by-byte comparison in MIPS.

1

Runtime heap in .data

Add a heap block and a heap pointer to your .data section. The heap pointer is a word that holds the next free address.

codegen.c — heap bootstrap in .data
_heap_ptr:  .word _heap_mem   # pointer to next free byte
_heap_mem:  .space 4096       # 4 KB should be enough

Emit these lines once, after your string literals. The heap pointer is initialised to the start of _heap_mem by the .word _heap_mem directive.

2

string_concat built-in

Emit a MIPS subroutine _string_concat that takes two string addresses in $a0 and $a1, allocates space on the heap, copies both strings, and returns the new address in $v0. Use lb/sb to walk bytes; stop at the null terminator.

MIPS _string_concat (sketch)
_string_concat:
    # compute len(a0): walk until lb == 0
    # compute len(a1): same
    # total = len0 + len1 + 1
    lw   $t8, _heap_ptr      # destination address
    # copy a0 bytes to $t8, then a1 bytes
    # write null terminator
    # advance heap pointer by total
    sw   $t8, _heap_ptr      # WRONG: see note below
    # actually: add $t9,$t8,total; sw $t9,_heap_ptr
    move $v0, $t8
    jr   $ra

When string_concat is called in the compiler, intercept it in codegen.c like you do with output_string: load the two argument addresses into $a0/$a1, jal _string_concat, and store $v0 into the result variable.

3

string_equal built-in

Emit a MIPS subroutine _string_equal that takes two addresses in $a0/$a1 and returns 1 (equal) or 0 (not equal) in $v0. Walk both strings simultaneously with lb; at each position compare bytes. If they differ return 0. If both reach null at the same time return 1.

💡

Tip: Use a loop label like _seq_loop with a suffix number (e.g., _seq_loop_0) so multiple calls don't collide. Generate the suffix from a static counter in codegen.c.

MIPS Quick Reference

Syscalls used in this extension

  • $v0 = 1 — print integer (existing)
  • $v0 = 4 — print string: $a0 = address of null-terminated string
  • $v0 = 11 — print character: $a0 = ASCII code (bonus)

Common pitfalls

  • Forgetting the null terminator when copying strings in the heap
  • Calling sw _heap_ptr instead of sw $tX, _heap_ptr (use a register as intermediate)
  • Not spilling registers before calling _string_concat — the subroutine clobbers $t registers
  • String literals with escape sequences: \" should become " in the stored text
