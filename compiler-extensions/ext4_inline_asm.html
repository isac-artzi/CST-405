Inline
Assembly

Add an asm("...") statement that passes raw MIPS instructions through the compiler verbatim, then extend it with %0-style variable operands that are automatically resolved to stack offsets.

📚 3 files modified ⏰ 2 × 75-min sessions 🔥 Difficulty: Light-Moderate 🆕 Easiest option with great "cool factor"

Goals & Scope

C-minus — session 1 goal
/* Raw passthrough: print 42 using a hand-written syscall */
asm("li $v0, 1\nli $a0, 42\nsyscall\n");
/* expected output: 42 */
C-minus — session 2 goal
int x;
x = 100;
asm("lw $a0, %0\nli $v0, 1\nsyscall\n", x);
/* %0 is replaced by the frame offset of x, e.g. -8($fp) */
/* expected output: 100 */

Files to modify

  • scanner.l — add asm keyword token
  • parser.y + ast.h/ast.c — NODE_ASM_STMT with string + variable list
  • tac.c/tac.h — TAC_ASM instruction (passes string through)
  • codegen.c — emit verbatim (session 1), substitute %N (session 2)

Why Inline Assembly?

Real compilers (GCC, Clang, MSVC) all support inline assembly for low-level operations that cannot be expressed in the high-level language: special instructions, precise register control, or performance-critical inner loops. By adding this feature you are opening a deliberate "trap door" in your compiler: the front end stops checking the code inside the asm() block.

This extension is deliberately simple to implement, which gives you time to think deeply about the implications — you cannot do register allocation, optimize, or even parse the inline assembly, so the surrounding compiler state must be stable when control reaches the block.

⚠

Important design note: Before entering an asm() block your codegen must spill all registers to memory (call spillAllRegisters()). The inline MIPS code may clobber any $t register, so all live values must be in memory before the block executes, and all registers must be invalidated after it.

Session 1 — Pass-Through Assembly

🎯

Goal: The compiler accepts asm("...");, creates a TAC node for it, and emits the string contents verbatim into the output file without any processing.

1

Lexer — asm keyword

In scanner.l, add one keyword rule in the same block as if, while, etc.:

scanner.l
"asm"   { return ASM_KW; }

Declare in parser.y: %token ASM_KW. No new lexer state is needed because the string body is captured by your existing STRING_LITERAL rule (which you added or will add). If you haven't added that rule, add it now — it's the same rule needed for Extension 1.

2

AST node — NODE_ASM_STMT

Add to ast.h:

ast.h
NODE_ASM_STMT,   /* inline asm block */
                 /* sval = asm string text             */
                 /* children = variable operand list   */

In parser.y, add a grammar rule inside stmt:

parser.y
stmt: ASM_KW '(' STRING_LITERAL ')' ';'
      { $$ = makeAsmStmt($3, NULL); }
    | ASM_KW '(' STRING_LITERAL ',' operand_list ')' ';'
      { $$ = makeAsmStmt($3, $5); }
    ;

For session 1, you only need the first rule. The operand_list will be added in session 2.

3

TAC & codegen passthrough

In tac.h add TAC_ASM. In tac.c, when visiting NODE_ASM_STMT, emit one TAC_ASM instruction carrying the raw string in arg1.

In codegen.c, handle TAC_ASM:

codegen.c — TAC_ASM handler (session 1)
case TAC_ASM:
    spillAllRegisters(out);        /* flush dirty regs to memory */
    fprintf(out, "%s", instr->arg1);  /* emit verbatim */
    invalidateAllRegisters();      /* asm may have clobbered $t regs */
    break;
💡

Multiline support: Your string literal rule should already preserve newlines inside the string (they are literal characters between the quotes). The fprintf passthrough emits them unchanged. Test that "li $v0, 1\nli $a0, 42\nsyscall\n" — where \n is a literal backslash-n escape in the source — becomes actual newlines in the output. You may need to process the \n escape in the lexer rule when copying the string.

  • Surrounding C-minus variables are not corrupted (registers are spilled/invalidated)

Session 2 — Operand Substitution

🎯

Goal: Allow asm("...", x, y) where %0 in the string is replaced by the frame offset of x, %1 by the frame offset of y, etc.

1

Design: what %0 means

Given asm("lw $a0, %0", x), the compiler knows that x is at frame offset -8($fp). It substitutes %0 with the string "-8($fp)", producing lw $a0, -8($fp). This is the MIPS addressing mode for a memory operand.

Before / After substitution
/* Source: */  asm("lw $t0, %0\nadd $t0, $t0, 1\nsw $t0, %0\n", x);
/* Emitted: */  lw  $t0, -8($fp)
                add $t0, $t0, 1
                sw  $t0, -8($fp)
2

Parsing the operand list

In parser.y, add the operand_list rule and complete the second asm variant:

parser.y
operand_list:
    operand_list ',' ID  { $$ = appendOperand($1, makeIdNode($3)); }
  | ID                  { $$ = makeOperandList(makeIdNode($1)); }
  ;

Store the operand list as child nodes of NODE_ASM_STMT (use the children[] array that other nodes use). In tac.c, extend TAC_ASM to carry both the raw string and an array of variable names (resolve each variable name to its TAC temp or direct name at this point).

3

Placeholder substitution in codegen

Write a helper function substituteOperands(const char *tmpl, char **vars, int numVars) in codegen.c. Walk the template string character by character. When you encounter % followed by a digit N, replace it with the frame offset string for vars[N].

codegen.c — substituteOperands sketch
char *substituteOperands(const char *tmpl,
                          char **vars, int n) {
    static char buf[4096];
    int i = 0, j = 0;
    while (tmpl[i]) {
        if (tmpl[i] == '%' && isdigit(tmpl[i+1])) {
            int idx = tmpl[++i] - '0';
            int off = getFrameOffset(vars[idx]);
            j += sprintf(buf+j, "%d($fp)", off);
        } else {
            buf[j++] = tmpl[i];
        }
        i++;
    }
    buf[j] = '\0';
    return buf;
}

Call this function from the TAC_ASM handler and emit the result instead of the raw template.

⚠

Remember: Still call spillAllRegisters() before emitting and invalidateAllRegisters() after — the substituted asm code may still write to any $t register.

✓ Session 2 Checkpoint

test_asm2.c
int x; int y;
x = 10;
y = 20;

/* Use inline asm to add x and y and print the result */
asm("lw $t0, %0\nlw $t1, %1\nadd $a0,$t0,$t1\nli $v0,1\nsyscall\n", x, y);
/* expected: 30 */

/* Increment x in-place via asm */
asm("lw $t0, %0\naddiu $t0,$t0,1\nsw $t0, %0\n", x);
print(x);
/* expected: 11 (x was 10, incremented by asm) */
  • Generated .s shows correct offsets substituted for %0, %1
  • After the asm block x = 11 is visible to the C-minus code that follows
  • Operands with multiple variables in one block all resolve to distinct, correct offsets

Challenge Extensions

  • Support %=out:x modifier — emit a sw after the block to flush $t0 back to x
  • Support %=in:x modifier — emit a lw before the block to load x into $t0
  • Support multi-line block syntax: asm { line1; line2; } without the string quotes
  • Emit a warning if a %N operand index is out of range
