switch: Linear Chain or Jump Table

Lower it by hand with fall-through, then cost both implementations against four different case distributions.

All topics  ›  Topic 5  ›  Activity 4
Format pairsTime 50 min

The point

switch is the first construct where the obvious implementation and the fast implementation genuinely differ, and where the right answer depends on the input.

Do this

  1. Lower this by hand using the dispatch-then-bodies pattern. Get the fall-through right — case 2 has no break.
    switch (x) {
    case 1: print(10); break;
    case 2: print(20);
    case 3: print(30); break;
    default: print(0);
}
  2. Hand-execute for x = 1, 2, 3, 9. For x = 2, what prints? Two numbers. Confirm you understand why before implementing anything.
  3. Design the jump table version on paper for the same switch. What goes in the table? What happens for a value outside the case range? What happens for case 1, case 5 with nothing between?
  4. Cost it. For each of these, say which implementation you would choose and why:
    • 3 cases with values 1, 2, 3
    • 3 cases with values 1, 1000, 50000
    • 200 cases with values 1..200
    • 200 cases with values scattered over 0..2,000,000
  5. Implement the linear chain and verify against your hand execution.
  6. Semantic checks. Add two: at most one default, and no duplicate case values. Test both. Why can neither be a grammar rule?

Deliverable

Your hand lowering, the four-value execution table with x = 2 explained, your jump-table design, the four costing decisions, a working implementation, and both semantic checks with their test cases.
