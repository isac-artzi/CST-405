MIPS vs ARM — What Would Actually Change

Hand-translate one function, then mark every file in your compiler as unchanged, edited, or rewritten.

All topics  ›  Topic 5  ›  Activity 6
Format pairsTime 45 min

The point

Answer the retargeting question with evidence rather than a feeling. The Topic 5 objective asks you to compare MIPS and ARM code generation; the useful comparison is about your own compiler's structure.

Do this

  1. Take one function — something with an if and a loop — and get the MIPS your compiler produces. Print it out.
  2. Hand-translate it to ARM. You do not need to be fluent; you need the shape. The mappings you need:
        MIPS                          ARM (A32)
    li   $t0, 5                   mov  r0, #5
    add  $t2, $t0, $t1            add  r2, r0, r1
    lw   $t0, 8($sp)              ldr  r0, [sp, #8]
    sw   $t0, 8($sp)              str  r0, [sp, #8]
    slt  $t2, $t0, $t1            cmp  r0, r1        (sets flags)
    beq  $t2, $zero, L            b.ge L             (branches on flags)
    jal  fn_f                     bl   fn_f
    jr   $ra                      bx   lr
  3. Count. How many instructions in each version? Where did the counts differ, and why?
  4. The interesting difference. On ARM (A32) most instructions can be predicated. Rewrite if (a > 0) x = 1; using cmp and movgt with NO branch at all. Compare against the MIPS version.
  5. Now the real question. Go through your compiler file by file and mark each one unchanged, small changes, or rewritten for an ARM back end. Then say, in one sentence, what that list tells you about why the compiler has an IR.
  6. Within codegen.c, list the specific functions that would change. Be precise — this is the answer to the objective.
What step 5 should come out as

scanner.l, parser.y, ast.*, semantic.* and tac.*: unchanged. symtab.*: unchanged in interface, possibly different word size. codegen.*: rewritten. Roughly 85% of the compiler is target-independent, and that is not an accident — it is what phase 4 exists to buy you.

Deliverable

Both listings side by side with instruction counts, your predicated version from step 4, the file-by-file table, and the list of functions in codegen.c that would change.
