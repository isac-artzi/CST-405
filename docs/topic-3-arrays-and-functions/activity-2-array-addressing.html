Arrays Are Address Arithmetic

Do base + index×4 by hand, then make the compiler do it — for local, global and parameter arrays.

All topics  ›  Topic 3  ›  Activity 2
Format pairs, at a laptopTime 50 min

The point

Do the address arithmetic by hand before you make the compiler do it. Off-by-four is a very cheap mistake to make and a very expensive one to find in generated assembly.

Do this

  1. On paper. int a[5]; sits at offset 12 in the frame. Write the byte address of a[0], a[3], and a[i]. Then write the MIPS to load a[i] into $t4, assuming i is in $t2.
  2. Why sll $t, $t, 2 and not mul $t, $t, 4? Both work. Time them if you like — SPIM will tell you the instruction count. Write down which is faster and why.
  3. Implement createArrayDecl, createArrayIndex, the two grammar rules, and the TAC_ARRAY_LOAD / TAC_ARRAY_STORE cases in codegen.c.
  4. Test with a local array first, then a global one. They take different paths through arrayBaseReg; make sure you know which path each one took by reading the generated .s.
  5. Break it deliberately. Read a[99] from a 5-element array. What happens? Nothing stops you — there is no bounds check in this language. Find out what memory you just read.
Global arrays and .align

.asciiz leaves the assembler's location counter on an odd byte. If a .space or .word follows it without .align 2, every lw on that array raises an address-error exception in SPIM. It is a classic first bug and the error message does not obviously point at the cause.

Deliverable

Your hand-written address arithmetic and MIPS from step 1, your answer to step 2, a working array test, and one paragraph on what step 5 produced. Feeds Lab Question 14.
