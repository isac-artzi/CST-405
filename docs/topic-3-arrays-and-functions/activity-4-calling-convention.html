Trace a Call, Including a Nested One

$a0–$a3, $v0, $ra, and why f(1, g(2)) works at all.

All topics  ›  Topic 3  ›  Activity 4
Format pairs, at a laptopTime 50 min

The point

Trace a call through the register conventions, including the case that breaks naive implementations: a call inside a call.

Do this

  1. Predict the TAC for f(1, g(2)) — write the ARG and CALL instructions in order. Then compile and compare.
  2. Explain the ordering. Both calls emit ARG instructions into the same buffer. Why does the inner CALL take the right ones? (Read the TAC_CALL case in codegen.c.)
  3. Write a recursive function — factorial is fine — and run it for n = 5. Then draw the stack at the deepest point: how many frames, and what is in each $ra slot?
  4. Find the register limit. Write a function taking five parameters. What does the compiler say? Is that a good error message? Improve it if not.
  5. Design. Sketch how you WOULD pass a fifth argument. Real MIPS pushes it on the stack. Where exactly — above the caller's frame or below it? Who pops it? Write the two-line answer.
On step 2

A CALL consumes the LAST n buffered arguments, where n comes from the CALL instruction itself. Work through f(1, g(2)) with that rule and watch it come out right — then work through f(g(1), 2) and watch it come out right for a different reason.

Deliverable

Your predicted vs actual TAC, your answer to step 2, a stack diagram for factorial(5) at maximum depth, and your two-line answer to step 5. Feeds Lab Question 15.
