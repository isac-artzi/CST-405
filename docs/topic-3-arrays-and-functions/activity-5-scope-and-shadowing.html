Scope and Shadowing

Predict the output, draw the scope stack, then break exitScope on purpose.

All topics  ›  Topic 3  ›  Activity 5
Format pairsTime 40 min

The point

Shadowing is easy to describe and easy to get wrong. Predict, then verify.

Do this

  1. Predict the output of this program, line by line, before running it.
    int n;
int twice(int n) { return n + n; }
int main() {
    int m;
    n = 10;
    m = twice(3);
    print(n);
    print(m);
    { int n; n = 99; print(n); }
    print(n);
    return 0;
}
  2. Draw the scope stack at each print. Which entry does the lookup find, and how many scopes did it search?
  3. Run it without -q and find the scope-stack traces in the semantic analyzer output. Reconcile.
  4. Break it. Make exitScope() a no-op. Predict what now goes wrong, then run and confirm. What error appears, and is it the error you predicted?
  5. Break it the other way. Restore exitScope, and change isVarDeclaredInScope to search only the OUTERMOST scope. Which of the two symbol tables did you just break — the visibility one or the storage one?

Deliverable

Your line-by-line prediction, five scope-stack diagrams, and a paragraph on each sabotage. Feeds Lab Questions 11 and 16.
