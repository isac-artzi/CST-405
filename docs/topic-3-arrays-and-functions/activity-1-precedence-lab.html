Precedence and Associativity Lab

Six expressions, six trees, then break the precedence table and watch what changes.

All topics  ›  Topic 3  ›  Activity 1
Format pairsTime 40 minBring paper

The point

Precedence and associativity are two separate decisions that people routinely conflate. Separate them by hand.

Do this

  1. Draw the AST for each of these, using the precedence table from the lecture notes. Do not run anything yet.
    2 + 3 * 4
(2 + 3) * 4
17 - 5 - 3
-2 * 3
2 * -3
-8 / 2 / 2
  2. Evaluate each tree and write the number down.
  3. Check by compiling
    int main() { print(2 + 3 * 4); print(17 - 5 - 3); print(-8 / 2 / 2); return 0; }
    and running it in SPIM. Any disagreement is worth ten minutes.
  4. Change associativity. In parser.y, change %left '+' '-' to %right '+' '-'. Predict which of your six expressions change value, then rebuild and check.
  5. Remove %prec UMINUS from the unary-minus rule. Predict what happens to -8 / 2 / 2. Rebuild and check.
  6. Put it back.

The question worth taking away

Bison resolved an ambiguous grammar using declarations. The alternative was to rewrite the grammar into expr → term → factor layers. Write the layered version of just +, * and NUM, and say which you would ship in a compiler other people have to maintain.

Deliverable

Six trees with their values, the results of experiments 4 and 5, and your layered grammar with a one-paragraph argument. Feeds Lab Question 3.
