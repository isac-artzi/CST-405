Tokenize by Hand, Then by Machine

Write the token stream yourself, then find out where you and flex disagree — and why.

All topics  ›  Topic 1  ›  Activity 1
Format pairsTime 35–45 minBring laptop, one sheet of paper

The point

Before you let a tool tokenize for you, tokenize by hand. Every disagreement between your answer and the machine's is a rule you had not noticed you were assuming.

Do this

  1. On paper, alone, five minutes. Write the token stream for the line below. One token per line: KIND, then the text that matched. Do not run anything yet.
    x=y<=z*2;  // done!
  2. Compare with your partner. Where you differ, decide which of you is right and why before you look at any output. Write down each disagreement in one sentence.
  3. Now run it. Put that line in a file and run a scanner over it. On day one you have two options: your instructor will run the reference lexer on the projector, or — if you brought a working scanner forward from CST-301 — use your own:
    cd student/topic-1-lexical-analysis/lexer
make
./lexer yourfile.cm
  4. Account for every difference between your hand answer and the machine's. For each one, name the rule that explains it: longest match, first match, or 'that is not the scanner's job'.
  5. Then break it. Add a second line containing a character the language does not have — x = y @ z; — and confirm the error names the right line AND the right column. Count the columns by hand to check.

Questions worth arguing about

  • Is // done! a token? If not, what happened to it, and which phase would have to care if it were?
  • How many tokens is <=? How would you find out without reading the scanner source?
  • The line has no spaces around =. Did that change anything? Should it?

Deliverable

One shared file, activity1.md, containing:

  • your two hand-written token streams (before you ran anything),
  • the machine's output,
  • a numbered list of every disagreement, each with the one-sentence rule that explains it,
  • the error message from step 5, with the column verified by hand.

Bring it to the next class. You will need the token-kind list for Project 1.
