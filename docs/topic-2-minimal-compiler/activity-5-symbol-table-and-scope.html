Predict the Symbol Table

Write down what the table will hold before you run anything, then grade your own error messages.

All topics  ›  Topic 2  ›  Activity 5
Format pairsTime 45 min

The point

Predict what the symbol table will contain before you look. Being able to do that reliably is the difference between debugging and guessing.

Do this

  1. Predict. For the program below, write down what the symbol table holds after each line: names, and the stack offset each one gets.
    int a;
int b;
int sum;
a = 3;
b = 4;
sum = a + b;
print(sum);
  2. Check. Compile it WITHOUT -q and find the symbol table trace in the output. Reconcile any differences.
  3. Now break it three ways, and for each one predict the message before you run it:
    • int a; int a; — duplicate declaration
    • x = 1; with no declaration of x
    • print(y); with no declaration of y
  4. Grade your own error messages. For each, ask: does it give the LINE? does it name the IDENTIFIER? does it say what would fix it? Rewrite any that fail all three.
  5. Design question. Our table is a flat array searched linearly. Sketch what changes if it becomes a hash table. Which functions change? Which do not? Why does that answer matter?

Deliverable

Your predictions and the actual traces side by side; your three improved error messages; a short answer to step 5. Steps 3–4 feed Lab Question 5 directly.
