First Contact with Bison

One rule at a time, and a deliberate conflict so you learn to read parser.output.

All topics  ›  Topic 2  ›  Activity 2
Format pairs, at a laptopTime 50 min

The point

Get bison to talk to you. Its conflict reports are the most useful and least read output in this course.

Do this

  1. Build the given skeleton and confirm it compiles:
    cd student/topic-2-minimal-compiler/compiler
make
./minicompiler tests/t2_01_basics.cm out.s
    It will fail — the grammar is a placeholder. Read the message.
  2. Write ONE rule: program : stmt_list { root = $1; } and stmt_list : stmt | stmt_list stmt, with stmt : decl and decl : INT ID ';'. Nothing else. Build.
  3. Feed it a file containing only declarations. Confirm it parses.
  4. Now deliberately create a conflict. Add a second rule stmt : INT ID ';' alongside stmt : decl. Rebuild and read what bison says.
  5. Get the full report. Run bison -d -v parser.y and open parser.output. Find the state with the conflict. It shows you the exact item set — which symbols it had seen and what it could not decide between.
  6. Remove the conflict and add the remaining rules for assign and print_stmt.
parser.output is a gift

Nearly everyone in this course will, at some point, have a grammar with a conflict they do not understand. The answer is always in parser.output. Learning to read it today costs 15 minutes and saves an evening in Topic 5, where the dangling-else conflict arrives on schedule.

Deliverable

Your parser.y with all four statement forms parsing, plus the excerpt from parser.output showing the conflict you created in step 4 and one sentence explaining what bison could not decide.
