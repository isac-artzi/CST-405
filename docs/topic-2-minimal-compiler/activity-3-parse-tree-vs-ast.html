Parse Tree vs AST

Draw both, count the difference, and decide what your statement list should look like.

All topics  ›  Topic 2  ›  Activity 3
Format individual, then compareTime 40 min

The point

You are about to design a data structure that five later phases have to live with. Design it on paper first.

Do this

  1. Draw the parse tree AND the AST for
    int a;
int b;
a = 1 + 2;
b = a + a;
print(b);
  2. Count the nodes in each. Write both numbers down.
  3. For every node in the parse tree that is NOT in the AST, say in one phrase what it was for and why nothing downstream needs it.
  4. Design decision. Our NODE_STMT_LIST holds two children — a statement and 'the rest'. An alternative is a single node holding an array of statements. Sketch both for the five-statement program above.
  5. Argue it. Which is easier to build in a bison action? Which is easier to WALK in generateTAC? They may not be the same answer, and noticing that is the point.
A nudge on step 5

A left-recursive rule reduces one statement at a time, so an action naturally builds a linked structure — the array version has to grow and copy. But walking a linked list of lists means every visitor needs a special case for 'the child is itself a list', which is exactly the bug that will make your compiler silently skip statements. Look at how checkStmtList and generateTACStmtList handle it in the given code.

Deliverable

Both trees, both node counts, your list from step 3, and a short paragraph on step 5. This is Lab Question 6 nearly verbatim.
