break, and the continue You Are Not Implementing

A label stack, a depth counter, and why continue in a for loop surprises people.

All topics  ›  Topic 4  ›  Activity 3
Format pairsTime 45 min

The point

break looks trivial and is the first construct whose meaning depends on context rather than on its own text.

Do this

  1. Predict the target of each break below, then implement the break-label stack and check.
    while (a) {
    while (b) {
        break;        <- which loop does this leave?
    }
    break;            <- and this one?
}
  2. Implement the semantic check. A break outside any loop must be an error with a line number. Use a depth counter incremented around loop BODIES only — not around loop conditions. Explain why the condition is excluded.
  3. Test the error. Write a file with a top-level break; and confirm the message names the line.
  4. Design continue. You do not have to implement it. On paper: what label would it jump to in a while? In a for? The answers differ, and the difference is the reason continue in a for loop surprises people.
  5. Design labelled break. Java has break outer;. What would that require of your label stack? Two sentences.
On step 4

In a while, continue jumps to the top — the same label the back-edge targets. In a for, it must jump to the UPDATE, not the top, or the loop variable never advances and you have written an infinite loop. This is why for needs its own continue label even if you desugared it into a while.

Deliverable

Your predictions, a working break with a working error message, and written answers to steps 4 and 5.
