1 Arrays — Complex Variable Support

The compiler supports integer arrays: declarations with a fixed size, element access via index, and arrays as function parameters.

1.1 New AST Node Types

ast.h : lines 28–29

ast.h
/* Array declaration (NODE_ARRAY_DECL) */
struct {
    char* name;      /* Array name */
    int  size;       /* Number of elements (0 for params) */
    int  isParam;    /* 1 if function parameter, 0 otherwise */
} array_decl;

Two constructors exist: createArrayDecl(name, size) for declarations like int arr[10];, and createArrayParam(name) for parameters like int arr[] (size unknown, isParam=1).

ast.h
/* Array indexing (NODE_ARRAY_INDEX) */
struct {
    char* name;             /* Array name */
    struct ASTNode* index; /* Index expression */
} array_index;

Used for both reading (arr[i] as expression) and writing (arr[i] = expr as the LHS of assignment). The index field is itself an expression subtree, allowing computed indices like arr[i + 1].

1.2 Parser Grammar for Arrays

parser.y : lines 143–167, 205–208

Grammar Rules (click to expand)
parser.y
/* DECLARATION - int x; or int arr[10]; */
decl:
    INT ID ';'               { $$ = createDecl($2); free($2); }
    | INT ID '[' NUM ']' ';'  { $$ = createArrayDecl($2, $4); free($2); }
    ;

/* ASSIGNMENT - x = expr; or arr[i] = expr; */
assign:
    ID '=' expr ';'  { $$ = createAssign($1, $3); free($1); }
    | ID '[' expr ']' '=' expr ';' {
        ASTNode* lhs = createArrayIndex($1, $3);
        $$ = createAssign(NULL, $6);    // var is NULL for arrays
        $$->data.assign.arrayLHS = lhs; // store index node
        free($1);
    }
    ;

/* Array indexing in expressions */
expr:
    ...
    | ID '[' expr ']'  { $$ = createArrayIndex($1, $3); free($1); }
    ...
    ;
Design Decision
Array assignments use a special pattern: assign.var = NULL and assign.arrayLHS holds the NODE_ARRAY_INDEX node. This lets the rest of the compiler distinguish scalar vs. array assignments without adding a new statement type.

1.3 Memory Layout for Arrays

symtab.c : lines 47–69

Each array occupies size × 4 contiguous bytes on the stack. The symbol table stores the base offset.

Stack Layout for: int x; int arr[4]; int y; Offset Content 0 x (4 bytes) 4 arr[0] ┌ 8 arr[1] │ 16 bytes 12 arr[2] │ (4 elements) 16 arr[3] └ 20 y (4 bytes) arr element address = $sp + base_offset + (index × 4) e.g. arr[2] = $sp + 4 + (2 × 4) = $sp + 12

2.2 Parser Rules for Functions

parser.y : lines 74–109

Function Definition Grammar
parser.y
/* FUNCTION DEFINITION - int name(params) { body } */
func_def:
    INT ID '(' params ')' block {
        $$ = createFuncDef($2, $4, $6);
        free($2);
    }
    | INT ID '(' ')' block {
        $$ = createFuncDef($2, NULL, $5);
        free($2);
    }
    ;

/* Parameters can be scalar or array */
param:
    INT ID               { $$ = createParam($2); free($2); }
    | INT ID '[' ']'      { $$ = createArrayParam($2); free($2); }
    ;
Array Parameters
int arr[] creates a NODE_ARRAY_DECL with isParam=1 and size=0. This lets the compiler pass arrays by reference without knowing their size at the callee.
Function Call & Arguments Grammar
parser.y
/* FUNCTION CALL */
func_call:
    ID '(' args ')'  { $$ = createFuncCall($1, $3); free($1); }
    | ID '(' ')'       { $$ = createFuncCall($1, NULL); free($1); }
    ;

arg_list:
    expr                      { $$ = $1; }
    | arg_list ',' expr       { $$ = createArgList($1, $3); }
    ;

A function call can appear as a statement (func_call ';') or within an expression (result = add(x, y);). The parser handles both.

3 Symbol Table: Variables, Arrays, and Memory

symtab.h / symtab.c

3.1 Symbol Entry Structure

symtab.h
typedef struct {
    char* name;      /* Variable identifier */
    int   offset;    /* Stack offset in bytes (MIPS stack frame) */
    int   isArray;   /* 1 if array, 0 for scalar */
    int   arraySize; /* Element count (0 for non-arrays) */
} Symbol;

3.2 How addVar vs addArray Work

symtab.c:22
int addVar(char* name) {
    if (isVarDeclared(name)) return -1;  // duplicate check

    symtab.vars[count].name = strdup(name);
    symtab.vars[count].offset = nextOffset;
    symtab.vars[count].isArray = 0;
    symtab.vars[count].arraySize = 0;
    nextOffset += 4;   // one int = 4 bytes
    count++;
    return offset;
}

Allocates exactly 4 bytes, advances nextOffset by 4.

symtab.c:47
int addArray(char* name, int size) {
    if (isVarDeclared(name)) return -1;

    symtab.vars[count].name = strdup(name);
    symtab.vars[count].offset = nextOffset;
    symtab.vars[count].isArray = 1;
    symtab.vars[count].arraySize = size;
    nextOffset += size * 4;  // size × 4 bytes
    count++;
    return offset;
}

Allocates size × 4 contiguous bytes. The stored offset is the base of the array.

3.3 Per-Function Symbol Tables

Important: Symbol Table Reset
In codegen.c, every TAC_FUNC_BEGIN triggers initSymTab(), resetting the symbol table. This means each function has its own isolated set of variable offsets. Parameters are then added via TAC_PARAM instructions and stored from $a0–$a3 registers onto the local stack.

4 Semantic Analysis: Scopes & Function Checks

semantic.c

4.1 Two-Pass Architecture

Semantic Analysis Flow Source AST │ ▼ Pass 1: Register Functions ← Collect all function signatures │ (name, param count, param types) │ Enables forward references! ▼ Pass 2: Check Bodies ← Walk each function body: │ Enter function scope • Check var declarations │ Add params to scope • Check var usage │ Check statements • Validate function calls │ Exit function scope • Match argument counts ▼ Report errors/warnings
Scope Management Details
semantic.c
/* Scope stack: nested scopes like global → function → block */
typedef struct {
    char* names[MAX_VARS];
    int count;
} Scope;

static Scope scopes[MAX_SCOPE_DEPTH];  // stack of scopes
static int scopeDepth = 0;

/* Variable lookup walks from innermost to outermost scope */
static int isVarDeclaredInScope(char* name) {
    for (int depth = scopeDepth - 1; depth >= 0; depth--) {
        for (int i = 0; i < scopes[depth].count; i++) {
            if (strcmp(scopes[depth].names[i], name) == 0)
                return 1;
        }
    }
    return 0;
}

This is lexical scoping: an inner scope can see all variables from outer scopes. When a scope exits, its variables are freed.

Scope Stack Example ┌────────────────────────────────┐ │ Scope[0] GLOBAL │ │ globalA, globalB, sharedArr │ ├────────────────────────────────┤ │ Scope[1] Function 'main' │ ← enterScope() │ localArray, a, b, result │ ├────────────────────────────────┤ │ Scope[2] Block (if/while) │ ← nested block │ temp_var │ └────────────────────────────────┘

4.2 Function Symbol Table

The semantic analyzer checks:

  • No duplicate function definitions
  • Function calls reference defined functions
  • Argument count matches parameter count
  • Return statements only appear inside functions
  • Array sizes are positive integers
  • Variables/arrays declared before use (scoped lookup)
Enhanced Error Messages
This compiler produces detailed, boxed error messages with line numbers, suggestions, and examples. For instance, calling add(x) when add expects 2 parameters shows exactly how many arguments are missing and offers a fix.

5 Three-Address Code: Intermediate Representation

tac.h / tac.c

5.1 TAC Instruction Types for Functions & Arrays

Category Opcode Format Meaning
Functions TAC_FUNC_BEGIN FUNC_BEGIN name Start of function scope
TAC_FUNC_END FUNC_END name End of function scope
TAC_PARAM PARAM name Declare formal parameter
TAC_ARG ARG value Push argument for call
TAC_CALL r = CALL f, n Call f with n args, result in r
TAC_RETURN RETURN val Return value from function
Arrays TAC_ARRAY_DECL ARRAY_DECL a[n] Declare array of n elements
TAC_ARRAY_LOAD r = a[i] Load element into temp
TAC_ARRAY_STORE a[i] = v Store value into element

5.2 TAC Generation Example

Source: int square(int n) { int result; result = n * n; return result; }

TAC output
 1: FUNC_BEGIN square
 2: PARAM n
 3: DECL result
 4: t0 = n * n
 5: result = t0
 6: RETURN result
 7: FUNC_END square
  1. generateTACFuncDef() emits TAC_FUNC_BEGIN square
  2. generateParamTAC() walks param list, emits TAC_PARAM n
  3. generateTACStmt(NODE_DECL) emits TAC_DECL result
  4. generateTACStmt(NODE_ASSIGN):
    • generateTACExpr(BINOP '*') recurses left (VAR n) and right (VAR n)
    • Allocates temp t0, emits t0 = n * n (TAC_MUL)
  5. Assignment emits result = t0 (TAC_ASSIGN)
  6. Return emits RETURN result
  7. Function end emits TAC_FUNC_END square

5.3 TAC for Function Calls with Arguments

Source: result = sumFive(a, b, c, d, e);

TAC output
ARG a
ARG b
ARG c
ARG d

Key Pattern
Arguments are emitted before the CALL instruction via TAC_ARG. The code generator collects them and maps to MIPS registers $a0–$a3. The argument count is stored in the CALL instruction's arg2 field.

5.5 Optimization Pass

The optimizer applies constant folding and copy propagation to the TAC before code generation.

before optimization
t0 = 1 + 2     // both operands are constants
t1 = t0 + 3

after constant folding
t0 = 3         // folded: 1+2 = 3
t1 = t0 + 3    // can't fold yet (t0 is variable at this point)

6.1 Register Allocator

codegen.h
typedef struct {
    char varName[MAX_VAR_NAME]; /* What's in this register */
    int  isDirty;               /* Modified since last store? */
    int  inUse;                 /* Is register allocated? */
    int  lastUsed;              /* Timestamp for LRU eviction */
} RegisterDescriptor;

The allocator manages 10 temp registers ($t0–$t9) with LRU spillingWhen all registers are full, the Least Recently Used register is written back to memory ("spilled") and reassigned to the new variable..

Register Allocation Flow Need register for variable 'x' │ ▼ findVarReg("x") — Is x already in a register? │ │ YES NO │ │ Return it Find free reg? │ │ YES NO │ │ Assign it selectVictimReg() (LRU) │ spillReg() if dirty │ Assign freed reg

6.2 Function Call Convention (MIPS)

codegen.c : lines 688–735

Step TAC MIPS
1. Push arguments ARG a
ARG b		 move $a0, $tx
move $a1, $ty
2. Call function t0 = CALL add, 2 jal func_add
3. Retrieve result (implicit) move $tr, $v0
4. Inside callee: receive params PARAM a
PARAM b		 sw $a0, 0($sp)
sw $a1, 4($sp)
5. Return value RETURN result move $v0, $tx
jr $ra
Limitation: Max 4 Arguments
This compiler uses MIPS registers $a0–$a3 for argument passing. Functions with more than 4 parameters would need stack-based argument passing, which is not yet implemented. The test file sumFive works because the codegen collects up to MAX_ARGS=4 args — the 5th argument handling is a known limitation.

6.3 Array Access in MIPS

codegen.c : lines 772–889

MIPS for arr[i] (Array Load)
Generated MIPS
# Given: arr base at offset 8, loading arr[2]
    li   $t3, 2            # Load index
    sll  $t4, $t3, 2       # offset = index × 4
    addi $t5, $sp, 8       # addr = $sp + base_offset
    add  $t5, $t5, $t4     # addr = base + element_offset
    lw   $t6, 0($t5)       # Load value at computed address
Address Calculation
element_addr = $sp + base_offset + (index × 4)
The sll (shift left logical by 2) efficiently multiplies the index by 4.
MIPS for arr[i] = val (Array Store)
Generated MIPS
# Given: arr base at offset 8, storing 30 into arr[2]
    li   $t3, 2            # Load index
    li   $t7, 30           # Load value to store
    sll  $t4, $t3, 2       # offset = index × 4
    addi $t5, $sp, 8       # addr = $sp + base_offset
    add  $t5, $t5, $t4     # addr = base + element_offset
    sw   $t7, 0($t5)       # Store value at computed address

6.4 Label Naming Convention

Functions: func_<name> for non-main functions, main_start for main

Control flow: L0, L1, ... auto-generated labels for if/while branches

Entry point: Program jumps from main: to main_start (after stack allocation)

  1. Pass 1 already registered square with 1 parameter

No optimization applies here — the argument 5 is already a constant, and the CALL instruction cannot be folded. The TAC passes through unchanged.

Phase 6: MIPS Code Generation
Generated MIPS
    # Argument: 5
    li   $a0, 5            # Pass argument in $a0
    jal  func_square       # Jump and link (saves $ra)
    move $t0, $v0          # Get return value
    sw   $t0, 12($sp)      # Store to 'a' (offset 12)

# Meanwhile, inside func_square:
func_square:
    sw   $a0, 0($sp)       # Store param 'n' at offset 0
    # DECL result at offset 4
    lw   $t0, 0($sp)       # Load n
    lw   $t1, 0($sp)       # Load n again
    mul  $t2, $t0, $t1     # t2 = n * n
    sw   $t2, 4($sp)       # Store to 'result'
    lw   $t3, 4($sp)       # Load result
    move $v0, $t3          # Move to return register
    jr   $ra               # Return to caller

8 Self-Check Questions

Q1: How many bytes does int arr[5]; allocate on the stack?
  • 5 bytes
  • 20 bytes
  • 10 bytes
  • 4 bytes
Each int is 4 bytes in MIPS. 5 elements × 4 bytes = 20 bytes. See addArray() in symtab.c which computes size * 4.
Q2: Why does the semantic analyzer use two passes over the AST?
  • The first pass optimizes the AST, the second checks semantics
  • The first pass checks variables, the second checks functions
  • The first pass registers all function signatures so the second pass can validate calls (enabling forward references)
  • Two passes are required by the Bison parser
Pass 1 collects all function names and parameter counts into the function symbol table. Pass 2 then walks each function body and can validate calls to functions defined later in the file. Without this, main() calling square() (defined above it) would fail.
Q3: In the MIPS output, what instruction computes index × 4 for array access?
  • sll $t, $t, 2 (shift left logical by 2)
  • mul $t, $t, 4
  • addi $t, $t, 4
  • srl $t, $t, 2
sll (shift left logical) by 2 bits is equivalent to multiplying by 4 (22). This is a standard MIPS optimization — bit shifts are faster than multiplication.
Q4: What happens when the register allocator runs out of all 10 temp registers?
  • The compiler exits with an error
  • It switches to using $s registers
  • It increases the register count dynamically
  • It "spills" the least-recently-used register to memory and reuses it
The selectVictimReg() function finds the register with the oldest lastUsed timestamp (LRU policy). If that register is "dirty" (modified), spillReg() writes it back to memory with sw before reassigning the register.
Q5: How does the compiler distinguish x = 5; from arr[i] = 5; in the AST?
  • Different node types: NODE_ASSIGN vs NODE_ARRAY_ASSIGN
  • Same NODE_ASSIGN, but assign.var is NULL and assign.arrayLHS holds the index node for arrays
  • The parser generates different grammar productions that never share code
  • A flag field isArrayAssign on the ASSIGN node
Both use NODE_ASSIGN. For scalar assignments, assign.var = "x" and assign.arrayLHS = NULL. For array assignments, assign.var = NULL and assign.arrayLHS points to a NODE_ARRAY_INDEX node containing the array name and index expression.
Q6: How are function return values passed back to the caller in the generated MIPS?
  • Pushed onto the stack
  • Stored in $a0
  • Stored in $v0, then the caller copies it with move $tx, $v0
  • Stored in a global memory location
The callee executes move $v0, $tx followed by jr $ra. The caller then retrieves the value with move $tr, $v0. This follows MIPS calling convention where $v0 is the return value register.
