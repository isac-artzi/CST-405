Adding For-Loop Support
Part 1: Lexer, Parser & AST

In this session you will extend the front-end of the compiler to recognize, parse, and represent for loops as AST nodes. By the end of class your compiler will parse a for-loop and display a correct Abstract Syntax Tree — with semantic analysis and code generation left for Day 2.

  • Extend the AST node type enum and union to accommodate a new node type
  • Implement a constructor function and a print case for a new AST node
  • Build the compiler and verify the AST output for a test for-loop program

Part 1 — Lexer: Recognizing the for Keyword
15 min

The lexer is the first phase of compilation. It reads the raw source characters and groups them into tokens. The parser cannot recognize a for loop until the lexer can produce a FOR token.

1.1 Observe how existing keywords are tokenized scanner.l

Near the top of the rules section in scanner.l, you will find a set of string patterns for existing keywords (while, if, else, etc.). Each returns a corresponding token. Observe their placement relative to the general identifier rule [a-zA-Z_][a-zA-Z0-9_]*.

Answer the following before making any changes:

Reflection Questions

  1. If you placed the for keyword rule after the identifier rule, what would the scanner return when it sees the text for? Why?
  2. Flex's rule-selection strategy is: longest match wins; ties broken by rule order. Knowing this, where must the for rule be placed?
1.2 Add the FOR token rule scanner.l

Add a single scanner rule that matches the string "for" and returns the token FOR. The rule must be placed in the same block as the other keyword rules. The return value should be consistent with how other keywords (IF, WHILE, etc.) are returned — look at those patterns to confirm the style.

Note You cannot test this in isolation — the scanner depends on the token being declared in the parser. Complete Task 2.1 (token declaration) before attempting to rebuild.

Part 2 — Parser: Grammar Rules for the For-Loop
25 min

The parser defines the syntactic structure of valid programs using a context-free grammar. You will add the FOR token declaration, four new non-terminal types, and the production rules that describe how a for-loop is structured.

2.1 Declare the FOR token and new non-terminals parser.y

At the top of parser.y, find the %token line that declares existing keywords such as INT PRINT RETURN IF ELSE WHILE. Add FOR to this list.

Then find the %type <node> line that includes if_stmt while_stmt and similar non-terminals. Add the four new non-terminals to this line: for_stmt for_init for_cond for_update.

Easy to Miss Forgetting to add a non-terminal to the %type declaration causes a Bison error: "$$ of 'for_stmt' has no declared type". Both the %token and %type lines must be updated before adding the rules.
2.2 Add for_stmt to the stmt rule parser.y

Find the stmt production rule — it lists all valid statement types as alternatives separated by |. Add | for_stmt as a new alternative. Look at how while_stmt is added as a reference for the correct syntax.

Think about: does the order of alternatives in the stmt rule matter for Bison? Why or why not?

2.3 Write the four grammar productions parser.y

Add the four production rules after the while_stmt rule. The structure of a Bison rule is:

rule_name:
    production_one { /* action */ $$ = ...; }
    | production_two { /* action */ $$ = ...; }
    ;

For each rule:

  • for_stmt: FOR '(' for_init ';' for_cond ';' for_update ')' stmt. The action calls createFor() with four arguments. Before writing $3, $5, $7, $9, count the positional indices from left to right to verify those are correct for each component.
  • for_init: Two alternatives — an empty production (set $$ to NULL), and a scalar assignment without a trailing semicolon. Look at the existing assign rule in the parser to see the assignment pattern, but omit the trailing ';'.
  • for_cond: Two alternatives — empty (set $$ to NULL to signal "always true") and expr.
  • for_update: Mirror for_init — empty or scalar assignment without semicolon.
Counting Positional Indices In the rule FOR '(' for_init ';' for_cond ';' for_update ')' stmt, each token (including punctuation) occupies a position. FOR is position 1, '(' is position 2, for_init is position 3, and so on. Write out all 9 positions and their values before writing the action.

Discussion Question

  1. Why does the empty production for for_init set $$ to NULL rather than, for example, creating a special "empty" AST node? What would happen in later phases if you chose to create an empty node instead?
2.4 First build attempt — parser only

Run make from the CST-405-for-loop/ directory. The build will likely fail at the linking stage because createFor() is not yet declared or implemented. That is expected. Focus on the Bison output first:

  • If Bison reports syntax errors in parser.y, a production rule has a typo or structural error — re-examine your grammar rules.
  • If Bison reports new shift/reduce conflicts beyond the existing 1 (the dangling-else), your grammar is ambiguous — re-examine the optional productions.
  • If Bison reports undeclared type errors, you missed a %type declaration.
Interpreting Bison Conflicts One pre-existing shift/reduce conflict exists in this grammar (the dangling-else). If make reports exactly 1 conflict after your changes, your grammar is correct. Any new conflicts indicate an ambiguity in the rules you added.

Part 3 — AST: Node Type, Struct & Constructor
20 min

The AST is the compiler's internal model of the program. Every construct in the source language maps to a node type. You must define the for-loop's node type, its data layout, a constructor function, and a print case.

3.1 Add NODE_FOR to the NodeType enum ast.h

Open ast.h and find the NodeType enum. It lists all node types (e.g., NODE_IF, NODE_WHILE, NODE_BLOCK). Add NODE_FOR adjacent to NODE_WHILE to keep related items together. A comment describing the node's purpose is expected.

Note: the enum value itself is just an integer tag. The compiler will not enforce its meaning — that is your job in the constructor and in each phase that handles it.

3.2 Add the for_stmt struct to the ASTNode union ast.h

Inside ASTNode, there is a union that contains one struct per node type. Find the while_stmt struct — it has two pointer fields (condition and body). Add a new struct for for_stmt directly after it.

The for_stmt struct requires four struct ASTNode* fields:

  • init — the initialization statement; may be NULL
  • condition — the loop condition; may be NULL (meaning always true)
  • update — the per-iteration update; may be NULL
  • body — the loop body; should not be NULL

Include a comment for each field describing when it may be NULL. Other structs in the union provide the style pattern.

Union Memory Sharing All structs inside the union share the same memory. Naming a field in for_stmt the same as a field in another struct (e.g., naming it body when while_stmt also has body) is fine — they are in separate structs inside the union and accessed as node->data.for_stmt.body vs node->data.while_stmt.body.
3.3 Declare createFor() in the header ast.h

At the bottom of ast.h, find the section labeled "Control flow nodes" where createIf(), createWhile(), and createBlock() are declared. Add the declaration for createFor() in this section. The function takes four ASTNode* parameters and returns an ASTNode*. Follow the style of the adjacent declarations.

3.4 Implement createFor() in ast.c ast.c

In ast.c, find the createWhile() function. It is the closest structural analog to what you need to write. Implement createFor() immediately after it. Your implementation must:

  1. Allocate a new ASTNode using malloc(sizeof(ASTNode))
  2. Set node->type to NODE_FOR
  3. Set node->lineno to yylineno (same as all other constructors)
  4. Assign each of the four parameter values to the corresponding field in node->data.for_stmt
  5. Return the node pointer

The function should be approximately 8–10 lines. If it is significantly longer, revisit the pattern used by createWhile().

3.5 Add NODE_FOR case to printAST() ast.c

Find the printAST() function in ast.c. It is a large switch statement with one case per node type. Find case NODE_WHILE: and add case NODE_FOR: immediately after it.

The print case must:

  • Print "FOR\n" at the current indentation level
  • Print each of the four components with a labeled header ("INIT:\n", "CONDITION:\n", "UPDATE:\n", "BODY:\n")
  • For each component, if the pointer is non-NULL, recursively call printAST() at level + 2
  • If a component pointer is NULL, print an informative placeholder (e.g., "(empty)\n" for init/update, "(always true)\n" for condition)

Study how case NODE_IF: prints its optional else_stmt component — the same conditional-print pattern applies here.

3.6 Full build

Run make clean && make from the project directory. Address any compiler warnings or errors before moving to the checkpoint. Common issues at this stage:

  • Implicit function declaration for createFor → the declaration in ast.h is missing or the header was not saved
  • Incompatible pointer types → a positional index mismatch in the parser action block
  • Undefined reference to createFor → the implementation in ast.c is missing or has a typo in the function signature

✓ Day 1 Checkpoint — Verify Your AST Output

Create a test file named test_for_day1.c containing the following program:

int main() {
    int i;
    int sum;
    sum = 0;
    for (i = 0; i < 10; i = i + 1) {
        sum = sum + i;
    }
    print(sum);
}

Run: ./minicompiler test_for_day1.c test_for_day1.s

In the output, find the AST section (Phase 2). Your output should show a FOR node with all four labeled sub-sections. Verify each item:

  • The INIT section shows an ASSIGN node for i = 0
  • The CONDITION section shows a BINOP node with operator <
  • The UPDATE section shows an ASSIGN node for i = i + 1
  • The BODY section shows a BLOCK containing the sum assignment

If the compiler crashes or reports errors during semantic analysis or code generation — that is expected and will be fixed on Day 2. A well-formed AST in the output means Day 1 is complete.
