1 · Where We Are in the Compiler

Over the past two weeks you added loops to the compiler. Today we add if-statements — the other major form of conditional control flow. Much of the infrastructure you built for loops (TAC_IF_FALSE, TAC_LABEL, TAC_GOTO, branch instructions in MIPS) already exists. What is new is in the parser grammar and a subtle correctness issue in the code generator.

🔑 Key insight: An if-else is structurally similar to a while loop with the back-edge removed. Both compile down to the same three TAC primitives — a conditional jump, a label, and an unconditional jump.

⚠ The One Non-Obvious Change

Loops always re-execute the body, so register state never "diverges." If-statements create merge points — multiple paths converging on a single label. After a merge point the register allocator's idea of which registers hold which values may be wrong. We will fix this properly in Phase 7.

3 · Phase 1 — Lexer (scanner.l)

The lexer must recognize two new reserved words and return the corresponding tokens. Because identifiers are matched by a catch-all rule, reserved words must be listed before the identifier rule so Flex gives them priority.

/* Add these two lines with the other keyword rules */
"if"      { return IF;   }
"else"    { return ELSE; }
💡 Flex uses maximal-munch + first-match ordering. Because "if" is listed before the identifier pattern [a-zA-Z_][a-zA-Z0-9_]*, the word if will always be tokenised as IF, never as an identifier.

4 · Phase 2 — Parser (parser.y) and the Dangling-Else Problem

4.1 The grammar rule

/* Two productions: if-without-else and if-with-else */
if_stmt:
    IF '(' expr ')' stmt                     /* no else */
  | IF '(' expr ')' stmt ELSE stmt            /* with else */
  ;

4.2 The dangling-else ambiguity

Consider:

if (a) if (b) x = 1;  else  x = 2;

Which if does the else belong to? There are two valid parse trees:

❌ Wrong: else attaches to outer if

if (a) {
  if (b) x = 1;
}
else {      // outer else
  x = 2;
}

✅ Correct: else attaches to inner if

if (a) {
  if (b) x = 1;
  else {    // inner else
    x = 2;
  }
}

All C-family languages use the "nearest if" rule. Bison's default behaviour (prefer shift over reduce) already implements this, but it reports a shift/reduce conflict warning unless we make the intent explicit with precedence directives.

4.3 Resolving the conflict cleanly

/* In the %nonassoc declarations, LOWER_THAN_ELSE has lower precedence */
%nonassoc LOWER_THAN_ELSE   /* pseudo-token, never appears in scanner */
%nonassoc ELSE               /* higher prec → bison will SHIFT ELSE */

/* Then annotate the if-without-else rule: */
if_stmt:
    IF '(' expr ')' stmt %prec LOWER_THAN_ELSE
        { $$ = createIf($3, $5, NULL); }
  | IF '(' expr ')' stmt ELSE stmt
        { $$ = createIf($3, $5, $7); }
  ;
🔍 How the precedence rule works: When bison has just parsed IF ( expr ) stmt and sees ELSE as the lookahead, it compares the precedence of the reduction (LOWER_THAN_ELSE) with the precedence of the shift (ELSE). Since ELSE > LOWER_THAN_ELSE, bison shifts — consuming the ELSE and attaching it to the current (innermost) if. Zero conflict warnings.

5 · Phase 3 — Abstract Syntax Tree (ast.h / ast.c)

5.1 New node type

/* In the NodeType enum — add after NODE_FOR */
NODE_IF   /* if (condition) then_stmt [else else_stmt] */

5.2 Node data structure

/* In the ASTNode union — add with the other control-flow structs */
struct {
    struct ASTNode* condition;  /* condition expression          */
    struct ASTNode* then_stmt;  /* executed when condition true  */
    struct ASTNode* else_stmt;  /* executed when condition false */
                                 /* NULL if no else clause        */
} if_stmt;

5.3 Constructor function

ASTNode* createIf(ASTNode* condition,
                   ASTNode* then_stmt,
                   ASTNode* else_stmt) {
    ASTNode* node = malloc(sizeof(ASTNode));
    node->type = NODE_IF;
    node->lineno = yylineno;
    node->data.if_stmt.condition = condition;
    node->data.if_stmt.then_stmt = then_stmt;
    node->data.if_stmt.else_stmt = else_stmt;
    return node;
}

The else_stmt pointer being NULL vs. non-NULL encodes whether an else branch exists. Every later phase checks this pointer before processing the else.

6 · Phase 4 — Semantic Analysis (semantic.c)

The semantic checker walks the AST and verifies that variables are declared, functions are called correctly, etc. For if-statements it must:

Check the condition expression — all variables inside must be declared. A condition like x > y references x and y; both must be in scope.
Warn on constant conditions — if (0) creates dead then-code; if (1) creates dead else-code. These are valid but suspicious.
Recursively check the then-branch — any statements inside the then-block must be semantically valid.
Recursively check the else-branch — only if else_stmt != NULL. 
case NODE_IF:
    /* 1. Check the condition for undeclared variables */
    checkExpr(node->data.if_stmt.condition);

    /* 2. Warn if condition is a compile-time constant */
    if (node->data.if_stmt.condition->type == NODE_NUM) {
        warnConstantCondition(node);
    }

    /* 3. Check then-branch */
    checkStmt(node->data.if_stmt.then_stmt);

    /* 4. Check else-branch (only if it exists) */
    if (node->data.if_stmt.else_stmt) {
        checkStmt(node->data.if_stmt.else_stmt);
    }
    break;

ℹ Scope Rules for If-Statements

In our compiler, variables declared inside an if block are visible only within that block (each { } opens a new scope in the semantic analyzer). A variable declared in the then-branch is not visible in the else-branch or after the if-statement ends.

7 · Phase 5 — Three-Address Code Generation (tac.c)

7.1 The three building blocks

Loops already use these TAC instructions, so they are not new:

InstructionMeaningMIPS equivalent
IF_FALSE t goto LBranch if t == 0beqz $tX, L
GOTO LUnconditional jumpj L
LABEL LJump targetL:

7.2 If-without-else lowering

/* Source: if (x > 0) { print(x); } */

t0 = x > 0             ; evaluate condition
IF_FALSE t0 GOTO L_end  ; skip then-block if false
PRINT x                ; then-block
L_end:                 ; merge point

7.3 If-else lowering

/* Source: if (x > 0) { r = 1; } else { r = 0; } */

t0 = x > 0              ; evaluate condition
IF_FALSE t0 GOTO L_else  ; jump to else if false
r = 1                   ; then-block
GOTO L_end              ; skip else-block
L_else:                 ; else merge point
r = 0                   ; else-block
L_end:                  ; end merge point

7.4 TAC generation code (C implementation)

case NODE_IF: {
    char* labelElse = newLabel();   /* e.g. "L2" */
    char* labelEnd  = newLabel();   /* e.g. "L3" */

    /* Evaluate the condition */
    char* cond = generateTACExpr(node->data.if_stmt.condition);

    /* Choose jump target: else label (if else exists) or end label */
    if (node->data.if_stmt.else_stmt) {
        appendTAC(createTAC(TAC_IF_FALSE, cond, labelElse, NULL));
    } else {
        appendTAC(createTAC(TAC_IF_FALSE, cond, labelEnd,  NULL));
    }

    /* Generate then-branch code */
    generateTACStmt(node->data.if_stmt.then_stmt);

    if (node->data.if_stmt.else_stmt) {
        appendTAC(createTAC(TAC_GOTO,    labelEnd,  NULL, NULL));  /* skip else */
        appendTAC(createTAC(TAC_LABEL,   NULL,      NULL, labelElse));
        generateTACStmt(node->data.if_stmt.else_stmt);
    }

    appendTAC(createTAC(TAC_LABEL, NULL, NULL, labelEnd));
    break;
}

8 · Phase 6 — Optimizer (tac.c)

The optimizer already handles the TAC instructions produced by if-statements. No new code is needed. The existing passes simply do more work.

📐 Constant Folding in Conditions

If an if-condition is a constant expression like 5 > 3, constant folding evaluates it at compile time:

t0 = 5 > 3      → t0 = 1

This then feeds the branch optimizer below.

✂ Dead Branch Elimination

Once the condition is a constant, the optimizer eliminates the dead branch:

IF_FALSE 1 GOTO L  → (removed)
IF_FALSE 0 GOTO L  → GOTO L

The "always false" branch becomes an unconditional jump. The "always true" branch's conditional is deleted entirely.

📖 Example: if (0) { print(x); } compiles to an IF_FALSE 0 GOTO L_end. The optimizer replaces this with GOTO L_end, so the then-block is never reached — the print is completely eliminated from the output assembly.

9.2 The merge-point register problem (the tricky part)

The register allocator works perfectly for linear code. Problems arise at merge points: locations that can be reached by two different paths.

🐛 The bug: After processing if (x > 0) { result = 1; }, the allocator records "result is in $t0." When it then generates print(result) it emits move $a0, $t0. At runtime, if the branch was taken and skipped the assignment, $t0 does not hold result — it holds whatever was there before. 
; Generated (WRONG) assembly for: if (x>0){r=1;} print(r);
    sgt $t1, $t0, $t2       ; t = x > 0
    beqz $t1, L3            ; skip then-block if false
    li $t0, 1               ; r = 1 in $t0
    sw $t0, 8($sp)          ; and in memory
L3:                         ; ← merge point: $t0 may NOT hold r!
    move $a0, $t0           ; BUG: uses stale $t0
    li $v0, 1
    syscall

9.3 The fix: invalidate all registers at every label

case TAC_LABEL: {
    fprintf(output, "%s:\n", curr->result);

    /* ── CRITICAL: invalidate all register state ──────────────
     * A label is a merge point. Multiple code paths may arrive
     * here via fall-through OR via a branch. We cannot trust
     * that any register holds the value the allocator thinks it
     * holds.  Clearing the descriptors forces every subsequent
     * variable read to emit an lw from its stack slot, which is
     * ALWAYS correct because every variable assignment already
     * does an sw to memory.
     * ────────────────────────────────────────────────────────── */
    invalidateAllRegisters();
    break;
}
; Corrected assembly for: if (x>0){r=1;} print(r);
    sgt $t1, $t0, $t2       ; t = x > 0
    beqz $t1, L3
    li $t0, 1
    sw $t0, 8($sp)          ; r=1 written to memory
L3:
    ; ← invalidateAllRegisters() clears descriptors
    lw $t0, 8($sp)          ; CORRECT: reload r from memory
    move $a0, $t0
    li $v0, 1
    syscall

✅ Why This Always Works

Variables are written to their stack slot (sw) on every assignment, so memory is always current. TAC temporaries (t0, t1…) are freed immediately after use and never survive a branch. Therefore invalidating registers at labels, combined with always storing variables to memory, guarantees correctness regardless of which path was taken.

10 · End-to-End Worked Example

Source code:

int main() {
    int x;  int r;
    x = 10;
    if (x > 5) {
        r = 1;
    } else {
        r = 0;
    }
    print(r);
    return 0;
}

▸ AST

FUNC_DEF: main
  BLOCK
    DECL: x
    DECL: r
    ASSIGN: x = 10
    IF
      COND: BINOP(>)
        VAR: x
        NUM: 5
      THEN: BLOCK
        ASSIGN: r = 1
      ELSE: BLOCK
        ASSIGN: r = 0
    PRINT: VAR r
    RETURN: NUM 0

▸ Unoptimized TAC

FUNC_BEGIN main
DECL x
DECL r
x = 10
r = ?
t0 = x > 5
IF_FALSE t0 GOTO L0
r = 1
GOTO L1
L0:
r = 0
L1:
PRINT r
RETURN 0
FUNC_END main

▸ Generated MIPS

main_start:
  li $t0, 10
  sw $t0, 0($sp)   # x=10
  lw $t1, 0($sp)   # load x
  li $t2, 5
  sgt $t3,$t1,$t2  # x>5?
  beqz $t3, L0
  li $t0, 1
  sw $t0, 4($sp)   # r=1
  j L1
L0:
  # invalidate regs
  li $t0, 0
  sw $t0, 4($sp)   # r=0
L1:
  # invalidate regs
  lw $t0, 4($sp)   # load r
  move $a0, $t0
  li $v0, 1
  syscall

11 · Summary — What Changes at Each Phase

Lexer (scanner.l)
Add two keyword rules: "if" → IF and "else" → ELSE. Place them before the identifier catch-all.
Parser (parser.y)
Add the if_stmt grammar rule with two productions (with and without else). Use %nonassoc LOWER_THAN_ELSE / ELSE to resolve the dangling-else conflict without warnings.
AST (ast.h / ast.c)
Add NODE_IF to the enum, add a three-pointer struct (condition, then, else) to the union, and implement createIf().
Semantic (semantic.c)
Add a NODE_IF case: check the condition, warn on constants, recurse into both branches.
TAC (tac.c)
Add a NODE_IF case in generateTACStmt: generate two labels, evaluate the condition, emit IF_FALSE, generate both branches, emit GOTO and LABEL instructions.
Optimizer (tac.c)
No changes. The existing constant-folding and dead-branch-elimination passes already handle the TAC produced by if-statements.
Code Generator (codegen.c)
Add invalidateAllRegisters(). Call it in the TAC_LABEL case. This prevents stale register values from corrupting results after conditional branches.
