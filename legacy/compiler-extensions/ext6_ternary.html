Expression vs Statement: A Key Distinction

The ternary is an expression, not a statement. This means it must produce a value — a register or temporary variable — that can be used in a larger expression like x = (a > b) ? a : b or even print((n > 0) ? n : -n). The if/else statement you already have doesn't produce a value; the ternary must.

The TAC pattern for the ternary reserves a single result temporary and has both branches write into it:

TAC pattern — ternary
/* x = (a > b) ? a : b */
t0 = a > b
IF_FALSE t0 GOTO L_false
t1 = a           ← true branch writes into t1
GOTO L_end
L_false:
t1 = b           ← false branch writes into SAME t1
L_end:
x = t1

The key: t1 is allocated before the branch, and both branches write to it. After L_end, t1 holds the result regardless of which branch was taken.

Session 1 — The Ternary ? : Operator

🎯

Goal: Parse and generate correct code for cond ? true_expr : false_expr as an expression that yields a value.

1

Two new tokens

In scanner.l:

scanner.l
"?"   { return QMARK; }
":"   { return COLON; }

In parser.y: %token QMARK COLON.

⚠

Watch out: If your switch statement uses : as a literal character token, the lexer already handles it. Check whether your scanner already returns ':' as a character token or if you need a named token. Using a named token COLON avoids ambiguity.

2

Precedence and grammar rule

In C, ternary has lower precedence than comparison but higher than assignment. In parser.y, declare it in the %left/%right section. Place it just above %right '=' (assignment). Use %right for right-associativity (nested ternaries associate right-to-left in C).

parser.y — precedence block (excerpt)
/* lowest precedence */
%right '='
%right QMARK COLON     /* ternary — just above assignment */
%left OR
%left AND
%left EQ NEQ
%left LT GT LEQ GEQ
%left '+' '-'
%left '*' '/'
%right UMINUS
/* highest precedence */

Then add the grammar rule inside expr:

parser.y — ternary rule
expr: expr QMARK expr COLON expr
      { $$ = makeTernary($1, $3, $5); }
3

AST node

In ast.h add NODE_TERNARY. The node has exactly three children: children[0] = condition, children[1] = true expression, children[2] = false expression. No new fields needed — the existing children[] array handles it.

ast.c — makeTernary
ASTNode *makeTernary(ASTNode *cond, ASTNode *t, ASTNode *f) {
    ASTNode *n = makeNode(NODE_TERNARY);
    n->children[0] = cond;
    n->children[1] = t;
    n->children[2] = f;
    n->numChildren = 3;
    return n;
}
4

TAC generation

In tac.c, handle NODE_TERNARY in generateTAC(). The pattern exactly mirrors how you handle NODE_IF, but you must allocate a result temp and write it in both branches:

tac.c — NODE_TERNARY
case NODE_TERNARY: {
    char *result  = newTemp();        /* result register */
    char *lFalse  = newLabel();
    char *lEnd    = newLabel();

    /* evaluate condition */
    char *cond = generateTAC(node->children[0]);

    /* branch if false */
    emitIfFalse(cond, lFalse);

    /* true branch: evaluate and store in result */
    char *trueVal = generateTAC(node->children[1]);
    emitAssign(result, trueVal);
    emitGoto(lEnd);

    /* false branch: same result temp */
    emitLabel(lFalse);
    char *falseVal = generateTAC(node->children[2]);
    emitAssign(result, falseVal);

    emitLabel(lEnd);
    return result;   /* result is the expression's value */
}
💡

Why no codegen changes? You reuse existing TAC opcodes: TAC_IF_FALSE, TAC_GOTO, TAC_LABEL, TAC_ASSIGN. The code generator already knows how to handle all of these. You get the ternary "for free" in codegen.

Session 2 — Short-Circuit && and ||

🎯

Goal: Rewrite && and || so that the right operand is only evaluated if necessary. Verify with a side-effect test.

1

Current vs correct behavior

Right now, the compiler likely handles a && b as an arithmetic operation: evaluate both a and b, then compute a != 0 && b != 0. This is wrong: if a is zero, b must never be evaluated.

The fix: change NODE_AND and NODE_OR to generate control flow (branches and labels) instead of arithmetic. Here are the two TAC patterns:

TAC pattern — A && B
result = 0                ← default: false
tA = <evaluate A>
IF_FALSE tA GOTO L_end   ← A is false: short-circuit, skip B
tB = <evaluate B>
IF_FALSE tB GOTO L_end   ← B is false: result stays 0
result = 1                ← both true
L_end:
TAC pattern — A || B
result = 1                ← default: true
tA = <evaluate A>
IF_TRUE tA GOTO L_end    ← A is true: short-circuit, skip B
tB = <evaluate B>
IF_TRUE tB GOTO L_end    ← B is true: result stays 1
result = 0                ← both false
L_end:
2

Implement AND short-circuit

In ast.h add NODE_AND_SC (short-circuit AND) — or just change the behavior of the existing NODE_AND if your compiler doesn't have a separate implementation for it. In tac.c, replace the arithmetic AND emission with the branch pattern above.

tac.c — NODE_AND_SC
case NODE_AND_SC: {
    char *result = newTemp();
    char *lEnd   = newLabel();

    emitAssignConst(result, 0);                /* default false */
    char *tA = generateTAC(node->children[0]);
    emitIfFalse(tA, lEnd);                     /* short-circuit */
    char *tB = generateTAC(node->children[1]);
    emitIfFalse(tB, lEnd);
    emitAssignConst(result, 1);               /* both true */
    emitLabel(lEnd);
    return result;
}
⚠

TAC_IF_TRUE: You need a TAC_IF_TRUE opcode for OR (branch when true, not false). Check tac.h — if it doesn't exist, add it alongside TAC_IF_FALSE, and add a matching case in codegen.c (it is just bne $tX, $zero, label).

3

Implement OR short-circuit

Mirror the AND implementation with the OR pattern. Note that you check IF_TRUE (branch when nonzero) instead of IF_FALSE, and the default value is 1 (true) while the final assignment (both false) is 0.

After both are implemented, verify that the TAC output for f() && g() shows the function call to g only in the path where f returned nonzero.

✓ Session 2 Checkpoint

test_shortcircuit.c
int calls;
calls = 0;

int f(int v) { calls = calls + 1; return v; }

/* AND: f(0) is false, f(1) must never be called */
int r1 = f(0) && f(1);
print(r1);        /* 0 */
print(calls);     /* 1  — f called once, not twice */

calls = 0;
/* OR: f(1) is true, f(0) must never be called */
int r2 = f(1) || f(0);
print(r2);        /* 1 */
print(calls);     /* 1  — f called once, not twice */

calls = 0;
/* Combined: ternary with short-circuit condition */
int a = 5; int b = 3;
int r3 = (f(a) > 0 && f(b) > 0) ? 1 : 0;
print(r3);        /* 1 */
print(calls);     /* 2  — both f(a) and f(b) evaluated */
  • TAC for f(0) && f(1) shows the jal f for the second call is inside a branch — not always executed
  • Side-effect counter proves the second operand was skipped
  • Result values (0/1) are correct in all cases
  • Ternary nested inside a short-circuit condition works correctly
