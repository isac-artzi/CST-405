MIPS: jal vs jalr

The existing compiler uses jal _func_name for all function calls — this encodes the target label directly in the instruction. To call through a function pointer, the target address is in a register at runtime, so you must use jalr $tX instead.

MIPS — direct vs indirect call
/* Direct call (current compiler) */
jal  _add             # address is encoded in the instruction

/* Indirect call (what you'll add) */
la   $t0, _add        # load address of _add into $t0
sw   $t0, -8($fp)     # store in fp variable
  ...
lw   $t0, -8($fp)     # load address back
jalr $t0              # call through register

Everything else (argument passing on the stack, $ra saving, return value in $v0) remains exactly the same as for direct calls.

Session 1 — Function Pointers & Indirect Calls

🎯

Goal: Declare function pointer variables, assign functions to them, and call through them using jalr.

1

Declaration syntax

Add a grammar rule for int (*fp)(int, int); style declarations. The simplest approach is to treat the parameter types as a count (since all types are int for now) rather than a full type list.

parser.y — fp declaration rule
/* type (*name)(param_types) */
decl: INT '(' '*' ID ')' '(' int_type_list ')' ';'
      { $$ = makeFuncPtrDecl($4, countList($7)); }

int_type_list:
    INT                         { $$ = makeList(1); }
  | int_type_list ',' INT      { $$ = appendList($1); }
  | /* empty */                { $$ = makeList(0); }
  ;

Add to ast.h: NODE_FUNCPTR_DECL (holds name and param count), NODE_FUNCADDR (holds a function name as sval), NODE_INDIRECT_CALL (holds the fp variable name and argument list).

For assignments like fp = add;, the right-hand side is an identifier that resolves to a function name. Detect this in semantic.c: when an identifier refers to a known function (not a variable), generate a NODE_FUNCADDR node instead of a regular variable read.

2

Symbol table: TYPE_FUNCPTR

In symtab.h add TYPE_FUNCPTR and a new field in SymbolEntry:

symtab.h
typedef struct SymbolEntry {
    char    name[64];
    VarType type;
    int     offset;       /* frame offset */
    int     fpParamCount; /* for TYPE_FUNCPTR: expected arg count */
    /* ... existing fields ... */
} SymbolEntry;

In semantic.c, when encountering an indirect call fp(a, b), look up fp in the symbol table, verify type == TYPE_FUNCPTR, and check that the argument count matches fpParamCount. Emit an error if it doesn't.

3

TAC and MIPS: la + jalr

Add to tac.h:

tac.h
TAC_FUNC_ADDR,     /* result = &funcName  — load function address */
TAC_INDIRECT_CALL, /* result = (*fp)(args) — call through register  */

In tac.c, NODE_FUNCADDR emits TAC_FUNC_ADDR with the function name in arg1. NODE_INDIRECT_CALL emits parameter-push TAC instructions (same as for direct calls), then a TAC_INDIRECT_CALL with the fp variable name in arg1.

In codegen.c, add two cases:

codegen.c — new cases
case TAC_FUNC_ADDR:
    /* la $tX, _funcName */
    fprintf(out, "\tla\t%s, _%s\n",
            regName(destReg), instr->arg1);
    storeReg(destReg, instr->result, out);
    break;

case TAC_INDIRECT_CALL:
    spillAllRegisters(out);
    /* lw $t0, fp_offset($fp) */
    fprintf(out, "\tlw\t$t9, %d($fp)\n",
            getFrameOffset(instr->arg1));
    fprintf(out, "\tjalr\t$t9\n");
    invalidateAllRegisters();
    break;
⚠

Use $t9 for jalr: MIPS convention uses $t9 (or $25) for indirect calls in some ABIs. Using a high-numbered $t register reduces the chance of clobbering an argument register. Also call spillAllRegisters() before the call — exactly as you do for direct calls.

Session 2 — Dot-Call Dispatch on Structs

🎯

Goal: Add a function-pointer field to structs and support obj.method(args) syntax, which is rewritten to a jalr call with &obj as an implicit first argument.

⚠

Prerequisite: This session builds on both Extension 2 (structs) and Session 1 of this extension. If you skipped Extension 2, ask your instructor for the struct starter code.

1

Function pointer fields in structs

Extend the struct type system (from Extension 2) to allow a field with function-pointer type. In the grammar, a field declaration can be either int name; or int (*name)(param_types);. Store the field type as TYPE_INT or TYPE_FUNCPTR in the FieldInfo struct. Function pointer fields still occupy 4 bytes (one word — an address).

The struct's total size calculation is unchanged: every field is 4 bytes regardless of whether it's an int or a function pointer.

2

Dot-call rewriting in tac.c

When the compiler encounters a call of the form expr.field(args), it should rewrite it at the TAC level to:

  1. Compute the address of expr (a TAC_ADDR_OF)
  2. Load the function pointer from the field offset (TAC_MEMBER_LOAD)
  3. Push &expr as the implicit first argument
  4. Push the explicit arguments
  5. Emit TAC_INDIRECT_CALL through the loaded pointer
TAC rewriting of dog.speak(&dog)
t0 = &dog               ← addr of struct
t1 = *(t0 + 4)          ← load speak field (offset 4)
PARAM t0                ← implicit self argument
CALL_INDIRECT t1        ← jalr through t1
3

Receiving self inside the method

Inside the callee function (e.g., dogSpeak), the first parameter is the struct pointer. It's passed exactly like any other integer parameter — it's just an address value. Accesses like self.sound use the member-access TAC you built in Extension 2 (or the pattern from session 1 of this extension for pointer-based access).

💡

Tip: The function signature int dogSpeak(struct Animal *self) is already valid syntax if you implemented struct pointer parameters in Extension 2. If not, simplify: declare the parameter as int self (it's just an address), and use pointer math to access fields by adding the offset: *(self + 0) for field at offset 0, etc.

✓ Session 2 Checkpoint

test_fp2.c — polymorphic dispatch
int catSound(int self)  { return 1; }  /* meow = 1 */
int dogSound(int self)  { return 2; }  /* woof = 2 */

struct Pet { int id; int (*speak)(int); };

struct Pet cat; cat.id = 10; cat.speak = catSound;
struct Pet dog; dog.id = 20; dog.speak = dogSound;

print(cat.speak(0));   /* 1 */
print(dog.speak(0));   /* 2 */

/* same call site, different behavior — polymorphism! */
int makeNoise(struct Pet *p) { return p.speak(0); }
print(makeNoise(&cat));  /* 1 */
print(makeNoise(&dog));  /* 2 */
  • Assigning different functions to the same field produces different behavior at the same call site
  • Generated MIPS uses lw to load the function address from the struct field, then jalr
  • makeNoise demonstrates true polymorphic dispatch — the call target differs based on the runtime contents of the struct
