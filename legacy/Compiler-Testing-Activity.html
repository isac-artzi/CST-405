C-Minus Compiler Testing Activity

CST-405 Compiler Design - Comprehensive Feature Testing

Activity Overview

Learning Objectives

By completing this activity, you will:

  • Systematically test all phases of your C-Minus compiler
  • Verify lexical analysis, parsing, semantic analysis, and code generation
  • Identify and document compiler behavior across various language features
  • Gain hands-on experience with comprehensive compiler testing methodologies
  • Understand the interaction between different compilation phases

This activity guides you through a systematic testing process for your C-Minus compiler. You will use the provided comprehensive test file (comprehensive_test.cm) and additional targeted tests to verify that your compiler correctly handles all language features.

Getting Started

Prerequisites

  • C-Minus compiler successfully built and executable
  • Comprehensive test file (comprehensive_test.cm)
  • Terminal/command line access
  • Text editor for examining output files
  • MARS or SPIM simulator (for MIPS execution testing)

Build Your Compiler

make clean
make
Note: Make sure your compiler builds without errors before beginning the testing process. Address any compilation warnings that may indicate potential issues.

  • Keyword identification

  • Number literals
  • Identifiers

Syntax Analysis

  • Grammar rules
  • AST construction

  • Error detection

Semantic Analysis

  • Type checking
  • Symbol table
  • Scope resolution
  • Declaration checking

Code Generation

  • MIPS assembly

  • Memory management
  • Instruction selection

Useful Testing Commands

Basic Compilation

./cminus comprehensive_test.cm

Trace All Phases

./cminus -spac comprehensive_test.cm

Trace Individual Phases

./cminus -s comprehensive_test.cm # Scanner only
./cminus -p comprehensive_test.cm # Parser only
./cminus -a comprehensive_test.cm # Semantic analyzer only
./cminus -c comprehensive_test.cm # Code generation only

With Optimization

./cminus -O1 comprehensive_test.cm # Level 1 optimization
./cminus -O2 comprehensive_test.cm # Level 2 optimization

Specify Output File

./cminus -o output.s comprehensive_test.cm

Testing Tips and Best Practices

  • Start Simple: Begin with basic features before testing complex combinations
  • Incremental Testing: Test one feature at a time to isolate issues
  • Keep Notes: Document your findings as you test each feature
  • Compare Output: Compare generated code with expected results
  • Use Smaller Tests: Create minimal test files for specific features when debugging
  • Check Intermediate Output: Use trace flags to see what happens at each phase
  • Test Edge Cases: Try boundary conditions (e.g., empty arrays, zero values, single iterations)
  • Verify Assumptions: Don't assume something works - test it explicitly
  • Read Error Messages: Pay attention to line numbers and error descriptions
  • Use Version Control: Keep track of working versions and changes

What to Document

As you work through this activity, keep track of the following:

  1. Successful Features: List all language features your compiler handles correctly
  2. Issues Found: Document any problems, bugs, or unexpected behavior
  3. Incomplete Features: Note any features that are partially implemented
  4. MIPS Code Quality: Comment on the efficiency and correctness of generated assembly
  5. Test Results: For each test case, note whether it passed or failed
  6. Observations: Any interesting findings about how your compiler works
Tip: Create a simple text document or spreadsheet to track your testing progress and findings. This will be valuable for understanding your compiler's capabilities and limitations.

Additional Test Ideas

Create Your Own Test Files

Beyond the comprehensive test file, consider creating focused tests for:

  • Deeply nested expressions (10+ levels of operator precedence)
  • Large arrays (100+ elements)
  • Many function calls in sequence
  • Complex recursive algorithms (Fibonacci, Tower of Hanoi)
  • Matrix operations using 2D arrays
  • Search and sort algorithms
  • Mathematical computations (GCD, prime numbers, etc.)

Performance Testing

  • Compare execution time of optimized vs. non-optimized code
  • Count number of instructions generated for equivalent operations
  • Analyze register usage efficiency
  • Measure compilation time for large programs

Reflection Questions

After completing your testing, consider these questions:

  1. Which compilation phase was the most challenging to implement correctly?
  2. What types of errors does your compiler detect effectively?
  3. How efficient is the generated MIPS code compared to hand-written assembly?
  4. What optimizations does your compiler perform, if any?
  5. If you were to continue developing this compiler, what would you improve first?
  6. How does your symbol table handle scoping and nested blocks?
  7. What was the most interesting bug you discovered during testing?
  8. How would you extend this compiler to support additional features?
