Background

What does a switch statement look like?

C — full switch anatomy
switch ( expression ) {
    case 1:
        statements
        break;

    case 2:               // empty body → falls through to case 3
    case 3:
        statements
        break;

    default:
        statements
        break;
}

New tokens required

Four new keywords + one new punctuation

  • switch — begins the statement
  • case — introduces a case label
  • default — the catch-all label
  • break — exits the switch (or a loop)
  • : (colon) — separates a label from its body

New grammar rules required

Think of a switch as three nested levels: the switch statement wraps a case list, which is a sequence of case clauses. Each clause has a label (case N: or default:) followed by zero or more statements.

BNF — switch grammar (informal)
switch_stmt   → SWITCH '(' expr ')' '{' case_list '}'

case_list     → ε
              | case_list case_clause

case_clause   → CASE NUM ':' opt_stmt_list
              | DEFAULT ':' opt_stmt_list

opt_stmt_list → ε
              | stmt_list

break_stmt    → BREAK ';'
⚠

Parser tip: opt_stmt_list must stop consuming statements when it sees case, default, or }. Bison handles this automatically because none of those tokens are valid statement starters in your grammar.

New AST nodes required

Three new node types

  • NODE_SWITCH — holds the controlling expression and a linked list of NODE_CASE nodes
  • NODE_CASE — holds the case value (int), an isDefault flag, the body statement list, and a next pointer to the following clause
  • NODE_BREAK — no additional data; its presence in the statement list is enough

Task 1 — Lexer scanner.l

Open scanner.l. Your job is to add keyword rules for the four new tokens and a rule for the colon character.

What to do

  1. Add four keyword rules before the general [a-zA-Z_][a-zA-Z0-9_]* identifier rule (order matters — keywords must be matched first).
  2. Add a rule for the ":" character and return the character token ':'.

Pattern

scanner.l Add these rules in the %% section 
/* ── Add these four keyword rules ── */
"switch"        { return SWITCH; }
"case"          { return CASE; }
"default"       { return DEFAULT; }
"break"         { return BREAK; }

/* ── Add the colon rule ── */
":"             { return ':'; }

/* The general identifier rule must come AFTER keywords */
[a-zA-Z_][a-zA-Z0-9_]*  { yylval.str = strdup(yytext); return ID; }
💡

Why order matters: Flex matches rules in the order they appear. If the identifier rule came first, the input switch would be returned as an ID token instead of the SWITCH keyword.

Quick check

Self-test before moving on

After adding the rules, run make. If it compiles without errors you are ready for Task 2. A compile error at this stage usually means the token name (e.g., SWITCH) is not yet declared in the parser — that is expected and will be fixed in Task 2.

%type <node> stmt_list stmt decl assign expr ...

/* add this line */
%type <node> switch_stmt break_stmt case_list case_clause opt_stmt_list
C

Add switch_stmt and break_stmt to stmt

Find the stmt: rule and add two new alternatives:

parser.y — stmt rule (partial)
stmt:
    decl
    | assign
    | ...
    | switch_stmt    /* ← add */
    | break_stmt     /* ← add */
    | block
    | func_call ';' { $$ = $1; }
    ;
D

Write the new grammar rules

Add the following four rules to the grammar section. Place them near the other control-flow rules (if_stmt, while_stmt, etc.) for readability.

parser.y — new grammar rules
/* SWITCH STATEMENT */
switch_stmt:
    SWITCH '(' expr ')' '{' case_list '}' {
        $$ = createSwitch($3, $6);
    }
    ;

/* CASE LIST - zero or more case/default clauses */
case_list:
    /* empty */ {
        $$ = NULL;
    }
    | case_list case_clause {
        /* Append the new clause to the END of the linked list */
        if ($1 == NULL) {
            $$ = $2;
        } else {
            ASTNode* tail = $1;
            while (tail->data.case_clause.next)
                tail = tail->data.case_clause.next;
            tail->data.case_clause.next = $2;
            $$ = $1;
        }
    }
    ;

/* CASE CLAUSE */
case_clause:
    CASE NUM ':' opt_stmt_list {
        $$ = createCase($2, 0, $4);   /* isDefault = 0 */
    }
    | DEFAULT ':' opt_stmt_list {
        $$ = createCase(0, 1, $3);   /* isDefault = 1 */
    }
    ;

/* OPTIONAL STATEMENT LIST (may be empty) */
opt_stmt_list:
    /* empty */ { $$ = NULL; }
    | stmt_list { $$ = $1; }
    ;

/* BREAK STATEMENT */
break_stmt:
    BREAK ';' {
        $$ = createBreak();
    }
    ;
⚠

Shift/reduce conflicts? Run bison -d parser.y 2&>&1 | grep conflict. A well-formed switch grammar with your existing dangling-else fix should introduce zero new conflicts. If you see conflicts, double-check that case_list is left-recursive (not right-recursive) and that opt_stmt_list has an empty alternative.

Task 3 — AST Types ast.h

Open ast.h. You need to add the three new node types to the NodeType enum and add two new struct fields to the data union.

A

Extend the NodeType enum

ast.h — NodeType enum (partial)
typedef enum {
    /* ... existing types ... */
    NODE_ARRAY_DECL,
    NODE_ARRAY_INDEX,
    /* ── Add these three ── */
    NODE_SWITCH,     /* switch ( expr ) { ... } */
    NODE_CASE,       /* case N: body  or  default: body */
    NODE_BREAK       /* break; */
} NodeType;
B

Add union fields

Inside the union in the ASTNode struct, add two new struct members after the existing array_index field:

ast.h — ASTNode union (add at the end)
/* Switch statement (NODE_SWITCH) */
struct {
    struct ASTNode* expr;    /* Controlling expression (evaluated once) */
    struct ASTNode* cases;   /* Linked list of NODE_CASE nodes */
} switch_stmt;

/* Case / default clause (NODE_CASE)
 * The 'next' pointer links this clause to the following one,
 * forming a singly-linked list through all cases in the switch. */
struct {
    int  value;              /* Case constant (unused when isDefault == 1) */
    int  isDefault;          /* 1 → default clause, 0 → case clause */
    struct ASTNode* body;    /* Statement list (NULL = empty/fall-through) */
    struct ASTNode* next;    /* Next case/default clause */
} case_clause;

Note: NODE_BREAK requires no extra fields — its presence in the statement list is all the information needed.

Add function prototypes

At the bottom of ast.h, add declarations for the three new constructor functions:

ast.h — function prototypes
/* Switch / case / break constructors */
ASTNode* createSwitch(ASTNode* expr, ASTNode* cases);
ASTNode* createCase(int value, int isDefault, ASTNode* body);
ASTNode* createBreak();

Task 4 — AST Functions ast.c

Open ast.c. Implement the three constructor functions and add cases to printAST() so the tree can be displayed.

Constructor functions

ast.c — createSwitch()
ASTNode* createSwitch(ASTNode* expr, ASTNode* cases) {
    ASTNode* node = malloc(sizeof(ASTNode));
    node->type = NODE_SWITCH;
    node->lineno = yylineno;
    node->data.switch_stmt.expr  = expr;
    node->data.switch_stmt.cases = cases;
    return node;
}
ast.c — createCase()
ASTNode* createCase(int value, int isDefault, ASTNode* body) {
    ASTNode* node = malloc(sizeof(ASTNode));
    node->type = NODE_CASE;
    node->lineno = yylineno;
    node->data.case_clause.value     = value;
    node->data.case_clause.isDefault = isDefault;
    node->data.case_clause.body      = body;
    node->data.case_clause.next      = NULL;  /* linked by parser */
    return node;
}
ast.c — createBreak()
ASTNode* createBreak() {
    ASTNode* node = malloc(sizeof(ASTNode));
    node->type   = NODE_BREAK;
    node->lineno = yylineno;
    return node;
}

printAST() cases

Inside the switch(node->type) in printAST(), add cases for the three new node types. Here is a suggested implementation:

ast.c — printAST() additions
case NODE_SWITCH:
    printf("SWITCH\n");
    for (int i = 0; i < level + 1; i++) printf("  ");
    printf("EXPR:\n");
    printAST(node->data.switch_stmt.expr,  level + 2);
    for (int i = 0; i < level + 1; i++) printf("  ");
    printf("CASES:\n");
    printAST(node->data.switch_stmt.cases, level + 2);
    break;

case NODE_CASE: {
    /* Walk the linked list of case/default clauses */
    ASTNode* c = node;
    while (c) {
        for (int i = 0; i < level; i++) printf("  ");
        if (c->data.case_clause.isDefault)
            printf("DEFAULT:\n");
        else
            printf("CASE %d:\n", c->data.case_clause.value);
        if (c->data.case_clause.body)
            printAST(c->data.case_clause.body, level + 1);
        else {
            for (int i = 0; i < level + 1; i++) printf("  ");
            printf("(empty - fall-through)\n");
        }
        c = c->data.case_clause.next;
    }
    break;
}

case NODE_BREAK:
    printf("BREAK\n");
    break;

Troubleshooting

  • Syntax error on "switch" → the token rule in scanner.l may be placed after the identifier rule. Move it above.
  • "createSwitch undeclared" → you forgot to add the function prototype in ast.h, or the function body in ast.c.
  • Segfault on printAST → check that createCase() sets next = NULL.
  • Wrong tree shape → check that your case_list rule appends to the end of the linked list, not the beginning.

Additional test: fall-through

Try a switch with a case that has no body (pure fall-through). Confirm the AST shows "(empty - fall-through)" for that clause:

Fall-through test
switch (x) {
    case 4:               // no body → falls through
    case 5: print(99); break;
    default: print(0);
}

Challenge

Extend the Language: Char Literals as Case Values

Standard C allows character literals as case values: case 'A':, case '\n':, etc. Currently your lexer has no rule for character literals.

Your challenge:

  • Add a lexer rule that matches a character literal (e.g., 'A') and returns a NUM token whose value is the ASCII code of the character (yylval.num = yytext[1];).
  • Extend your case clause grammar rule to also accept character literals as case values — since they are returned as NUM tokens, the grammar does not need to change, only the lexer does.
  • Test with a switch on a variable that holds an ASCII value and cases for 'A' (65), 'B' (66), etc.
  • Bonus: Improve the AST printer so that when a case value falls in the printable ASCII range (32–126) it prints both the integer and the character: CASE 65 ('A'):.
