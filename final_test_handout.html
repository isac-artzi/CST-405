Overview.  This is the capstone test for your C-minus compiler. The provided source file test_final.c exercises every language feature you have implemented across all phases of the semester. Your compiler must process this file correctly, produce valid MIPS assembly, and generate a performance comparison report.

1   Language Features Under Test

The test file covers the following six areas. Every area must compile and produce the expected output.

1 · Variables
  • int — scalar & array
  • float — scalar & array
  • boolean — true / false
  • char — single character literals
  • string — string literals
  • Global & local scope
2 · Functions
  • void functions (no return)
  • Functions returning int, float, boolean
  • No-parameter functions
  • Single & mixed-type parameters
  • Array parameters
  • Recursive functions
  • Functions accessing globals
3 · Loops
  • while loop
  • for loop
  • Nested loops (for inside for)
  • while inside for
  • Loop with array access
4 · Decisions
  • Simple if
  • if-else
  • if-else-if chain
  • Nested if
  • switch / case / default
  • Fall-through cases
  • Nested switch
5 · Integration
  • Fibonacci (iterative)
  • Fibonacci (recursive)
  • All types used together
  • Functions calling functions
6 · Performance
  • Unoptimized TAC output
  • Optimized TAC output
  • Instruction-count comparison
  • Constant folding target
  • Dead-code elimination target
  • Loop-invariant computation

2   Compilation & Execution Instructions

Step 1 — Build your compiler

make          # builds ./minicompiler

Step 2 — Compile the test file (unoptimized)

./minicompiler test_final.c test_final.s

Step 3 — Compile with optimization enabled

./minicompiler --optimize test_final.c test_final_opt.s

Step 4 — Run on the MIPS simulator

# Unoptimized
spim -file test_final.s

# Optimized
spim -file test_final_opt.s

Step 5 — Verify output

Both assembly files must produce identical output to the annotated expected values in test_final.c.

3   Performance Metrics Report

Your compiler must print (or write to a file) a performance report after each compilation run. The report compares the unoptimized and optimized compilation results side-by-side.

The report must include all of the following metrics:

Metric Unoptimized Optimized How to Measure
TAC instruction count count all emitted TAC lines count after optimization passes iterate tacList and optimizedList
MIPS instruction count count non-directive, non-label lines in .s same for optimized .s grep or counter in codegen.c
Compilation time (ms) wall-clock time for full compilation wall-clock time for optimized compilation clock() / gettimeofday() in main.c
Temporaries allocated tempAlloc.maxUsed tempAlloc.maxUsed after optimization read from TempAllocator
Constant-fold reductions — (n/a) count of folded expressions counter in optimizer
Dead-code eliminations — (n/a) count of removed TAC nodes counter in optimizer
MIPS simulation time (ms) execution time reported by SPIM execution time reported by SPIM spim stats or time spim …

Sample report format

===== Compiler Performance Report =====
Source file       : test_final.c

                     Unoptimized    Optimized    Reduction
TAC instructions :        142           98          31%
MIPS instructions:        310          207          33%
Temporaries used :         37           24          35%
Const folds      :          0           12
Dead code removed:          0            4
Compile time (ms):       12.4          14.1
Sim time (ms)    :       8.30          5.60         33%
========================================

Note: actual numbers will differ from this example. Compile time may be slightly longer with optimization enabled because the optimizer itself takes time — this is expected and worth discussing.

4   Deliverables

Submit a single ZIP archive named LastName_FirstName_CST405_Final.zip containing the following:

  • 1 All compiler source files — scanner.l, parser.y, semantic.c/h, tac.c/h, codegen.c/h, ast.c/h, symtab.c/h, main.c, and Makefile
  • 2 Test source file — the provided test_final.c (unmodified)
  • 3 Generated assembly files — test_final.s (unoptimized) and test_final_opt.s (optimized), both produced by your compiler from test_final.c
  • 4 Performance report — either printed to stdout during compilation (captured to a file) or written directly by your compiler as report.txt required format: see §3
  • 5 Unoptimized TAC listing — the raw TAC output emitted before any optimization passes run, saved as tac_unopt.txt
  • 6 Optimized TAC listing — the TAC output after all optimization passes, saved as tac_opt.txt
  • 7 Execution transcript — terminal output showing both SPIM runs (unoptimized and optimized) with matching expected values, saved as output_transcript.txt
  • 8 Written reflection — a short document (reflection.pdf or reflection.txt, 300–500 words) discussing: (a) the most challenging feature to implement, (b) what your optimizer does and why it improves the output, and (c) one thing you would do differently if starting over

5   Notes & Reminders

  • Do not modify test_final.c. The file will be compiled against a reference solution for comparison.
  • Each print() call must produce exactly one value per line on stdout. The expected value is annotated in the source.
  • Your compiler must handle the file without crashing, even if a particular feature is not fully implemented — emit a clear error message and continue.
  • Type coercion rules (e.g., int ÷ int vs. float ÷ int) must follow C semantics and be documented in your reflection.
  • The --optimize flag must be supported by your minicompiler binary. If you implement optimization unconditionally, document this clearly.
  • Partial credit is available for any section where your compiler produces correct output even if other sections fail.
